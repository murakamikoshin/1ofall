# 一寸先は嘘

挑戦者は部屋を抜けていく。各部屋には選択肢があり、正解は一つ。
**正解がどれかは、助言者だけに見えている。**
助言者はヒントを送るが、一部は嘘つきに配役されている。

> 答えを知っているのは、君以外の全員だ。

実装順序（仕様書 §12）に対する現在地。

### 手触りの確認で分かったこと

初版は**1周18秒**で終わり、しかも**多数決で解けていた**（全構成で生存率100%）。
根拠と直し方は `docs/PLAYTEST.md`、直した後の数字は `docs/BALANCE.md` にある。

いまは**1周 10〜13分**、1部屋あたりの生存率 74〜80%。

```bash
npm install

                     # http://localhost:5173/advisor.html  助言者（スマホ幅で見る）
```

```bash
npm run build            # 型検査 + 本番ビルド

npm run gen:sfx          # 効果音を作り直す

```

## 遊び方（挑戦者）

1. 部屋と選択肢が出る。正解は助言者だけが見ている
2. 発言枠の助言者が助言を送ってくる。**助言は伏せて届く**
3. **ひらけるのは3通だけ。誰の助言をひらくかを選ぶ** ← ここが一番重い決断
4. ひらいた助言を読んで、1つ選ぶ（60秒）
5. 生死が確定する

発言枠には嘘つきが2人いる。ひらいた3通のうち2通が嘘なら、まず死ぬ。

## 構成

```
index.html          挑戦者（将来 Tauri で包んで Steam 版本体にする）
advisor.html        助言者（無料ブラウザ・永続。Webフォントを読まない）

src/core/           通信も DOM も知らない純粋ロジック
  schema.ts         Zod。部屋データと通信メッセージの唯一の正
  limits.ts         数値制約と1周の骨格。zod を持たない（助言者ページ用）
  engine.ts         状態機械。配信・友達内・ソロで同じものが動く
  casting.ts        発言枠と嘘つきの配役。人数で自動調整、分岐しない
  advisor-gateway.ts 助言者の供給源。人間 / AI / なし を差し替える境界
  ai-advisors.ts    AI の助言者。ソロで人間の代わりに入る
  hint-writer.ts    助言の文面を組み立てる
  moderation.ts     助言の検閲。段階4のサーバーも同じ関数を通す
src/ui/             描画とそれ以外
  death-sequence.ts 死亡演出
  placeholder.ts    本番画像が来るまでの仮絵
data/rooms.core.json 部屋データ48室。コードから分離してある
```

### 設計上、崩してはいけない点

- **正解は挑戦者クライアントに渡らない。** `PublicRoom` 型が `correct` を持たないので、
  ネットワーク越しでも答えが挑戦者側へ流れる経路が型で塞がれている
- **助言者ページは配信映像に依存しない。** 盤面はサーバーから直接受け取る
- **人間かAIかで分岐しない。** `AdvisorGateway` の先を本体は知らない
- **助言者ページに zod もアニメーションライブラリも載せない。** 初速が命
- 部屋データは JSON。将来のプレイヤー投稿も同じ入口を通す
- **ひらける助言の数は `openLimit = 嘘つき数 × 2 − 1`。** これを緩めると
  全部見えていた頃と同じで、多数決で解ける。根拠は `docs/BALANCE.md`
