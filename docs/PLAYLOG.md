# 遊んだ記録

**95/100人が面白いと言う**ところまで持っていくための、
「実際に遊ぶ → 厳しく読む → 一番効くところだけ直す」のくり返し。

数字（`docs/RUBRIC.md`）はもう基準を満たしている。
ここで見るのはその外側——**その部屋で何が読めたか**。
助言の文面と手掛かりを並べて見ないと、面白いかどうかは分からない。

再現は `node tools/playtest-record.mjs <出力先> <モード> <周回数>`。
本物のブラウザで通しプレイし、部屋ごとの助言・持ち情報・選択・生死を書き出す。

---

## 1回目（2026-09-09 15:00 UTC）

通常モードを1周（16部屋）、全員挑戦者を2周、実際に遊んで記録を読んだ。

### 見たこと

**死ぬほど読みが楽になっていた。** 通常モードで区画1に16部屋いた結果、
記録が「正14 嘘1」と「正3 嘘12」に割れきって、
最後は一番上の数字に従うだけの作業になっていた。
死んで区画の最初に戻っても顔ぶれと配役はそのままなので、
**やり直すほど手の内が割れる**。難度の曲線が逆を向いていた。

**同じ文面が三人から出ていた。**

```
イチ（正12 嘘3） 「香の煙で間違いない」
テツ（正3 嘘12） 「香の煙で間違いない」
すず（正9 嘘6）  「香の煙で間違いない」
```

言い回しの型が5つしかないのに8人が喋るので、必ずぶつかる。
一字一句同じ文が並ぶと、人ではなく機械に見える。
「いつもの言い方が崩れたときに引っかかる」という読みも成立しない。

**問いの形が全部同じ。** 79部屋のうち **77部屋**が「〜ていいのはどれ？」。
選択肢も **51部屋**が同じ名詞の変奏（扉/扉/扉/扉/扉）。
読み合いは面白いのに、画面の見た目と文章が20部屋ずっと同じ型。
ここが一番「飽きた」に直結する。

### 直したこと

1. **死んだら顔ぶれごと引き直す。** 記録も消える。
   賭場が席を組み替える、という筋でもある
2. **言い回しの癖を人ごとに固定した。** でたらめに選んでいたのをやめ、
   `voiceOf(id)` に「どの型から使うか」を持たせた。
   同じことを言っても言い方が違うので人に見えるし、
   いつもの言い方が崩れたときに気づける。型も日英とも増やした
3. 助言を読むとき、**選択肢の名前を先に外してから言い回しを見る**ように直した。
   「動かない影」「A shadow that does not move」のように名前に否定語が入ると
   警告と読み違えていた（英語で1件、実在した）

型を足したときに見分けの正規表現を直し忘れて、
全員挑戦者の生き残りが 47%→38% に落ちる事故をその場で起こした。
同じことが二度と起きないよう `tools/test-locale.mjs` に
「迷いの型はすべて迷いと読まれるか」「断言の型が迷いと読まれないか」を足した。

### 数字

| | 前 | 後 |
|---|---|---|
| 通常（7項目） | 7/7 | 7/7 |
| 崖っぷち | 6/7 | 6/7 |
| 全員挑戦者 最後まで残る | 49.0% | 47.3% |
| 全員挑戦者 腕の差 | 41.0pt | 40.2pt |

死んだときの引き直しはルーブリックに出ない（あの物差しは1部屋ごとの
判断しか見ていない）。**実際に通しで遊ばないと見えない類の穴だった。**

### 次に見ること

部屋の単調さ。問いの形と選択肢の作りを散らす。
「〜ていいのはどれ？」以外の問い方（人を選ぶ、方角を選ぶ、順番を選ぶ）と、
同じ名詞の変奏ではない選択肢を混ぜる。

## 3回目（2026-09-10 01:30 UTC）

崖っぷちを遊んで、このモードの根っこが壊れていたのが分かった。

### 見たこと

**「黙らせる」を使うと嘘つきが一人消えるが、そのたびに積んだ記録が消えていた。**

崖っぷちは「信じられる一人を探す」遊びで、探す道具は「黙らせる」だけ。
なのに黙らせて席が空くと**顔ぶれごと引き直していた**ので、
探した結果（誰が嘘をついてきたかの記録）が毎回白紙に戻る。
道具を使うと探した成果が消える、という形になっていた。

`tools/brink-probe.mjs` を書いて実測した（黙らせるを使う打ち手と使わない打ち手）。

| | 1部屋あたり生存 | 踏破 | 1周 |
|---|---|---|---|
| 黙らせるを使わない | 45.5% | 0.0% | 11.0部屋 |
| 黙らせるを使う | **68.5%** | **38.5%** | 16.3部屋 |

**23ポイント違う。** このモードはこの道具を前提に成り立っている。
ところが**道具の存在をどこにも書いていなかった。**
気づかなかった人は45%・踏破0%で遊ぶことになる。壊れていると言われる。

ルーブリックの打ち手は助言を読むだけで黙らせるを使わないので、
崖っぷちの「生存率69%」はこの道具を使わない数字だった。
使った実測（68.5%）とほぼ同じなので、難易度そのものは当初の設計どおり。
**問題は難易度ではなく、遊び方が伝わっていないことだった。**

### 直したこと

1. **空いた席だけを入れ替える。** 残った人の記録は消さない。
   崖っぷちなら正直者はいつも一人のまま、という不変も保つ
2. **手引きに道具のことを書いた。**
   「一部屋に一人だけ黙らせられる。当たれば嘘つきが消え、
   外すと次の部屋が短くなる。これが探す道具だ」
3. `tools/brink-probe.mjs` を残した（`npm run sim:brink`）。
   ルーブリックだけ見ていると、モード固有の道具の価値が見えない

### 次に見ること

- 黙らせるの当たり率が55%しか出ていない。信用の低い者を狙う打ち手なのに
  当てずっぽう（4/5=80%）より悪い。打ち手側の粗さか、記録の付き方の問題か
- 通常モードの「黙らせる」も同じ道具として説明が要るか

## 4回目（2026-09-10 02:30 UTC）

崖っぷちの「黙らせる」を実測したところ、このモードの根っこが二重に壊れていた。

### 一つめ：道具が探した成果を消していた

黙らせた相手を**名簿から永久に外していた**ので、席が入れ替わって
そのぶん記録が消える。実測すると当たり率が54%で、
信用の低い者を狙う打ち手が当てずっぽう（4/5=80%）より悪かった。

席は残したまま、その区画のあいだ声だけ止めるようにした。→ 当たり率90%。

### 二つめ：直したら難易度が崩れた

永久に黙らせる形は「道具を連打すれば嘘つきが減る」ので、
**読まずに生き延びられた**。情報の道具にした途端 59.6%（踏破4%）まで落ちた。

命・部屋数を振っても数ポイントしか動かない。効いたのは**発言枠**だった。

| 発言枠 | 1部屋あたり生存 | 踏破 |

| 5（嘘つき4） | 59.6% | 4.0% |
| **4（嘘つき3）** | **71.7%** | **14.7%** |
| 3（嘘つき2） | 81.4% | 63.6%（易しすぎる） |

**ルーブリックが 6/7 → 7/7 になった**（生存率72.1%）。
このモードだけずっと1項目外していたのが、これで揃った。

### 三つめ：通常モードでは道具が死んでいた

同じ物差しで通常モードも測った。

| | 1部屋あたり生存 | 当たり率 |
|---|---|---|
| 黙らせるを使わない | 81.2% | — |

効かないうえに外すと次の部屋が短くなるので、**押すほど損をする罠**だった。
崖っぷち専用の道具にした。

（「確定した嘘つきの言葉を裏返して読む」打ち手も試したが、

「嘘つきを黙らせた」「外した。次の部屋が短くなる」を
読み上げ用にしか出していなかった。目で見ている人には何も出ていない。
**崖っぷちの中心の道具なのに、押した結果が分からなかった。**
HUD の下に出るようにした。

あわせて、黙らせて当たった相手を画面に残すようにした

### 五つめ：部屋の主の通報が3件たまるまで効かなかった

配信者が一人で通報しても何も起きない。自分の部屋なのに。
主の通報は一件で効くようにした（助言者どうしは結託を防ぐため据え置き）。

## 6回目（2026-09-10 05:00 UTC）　周期を速くした

1周を回すのに5分かかっていた。決め打ちで待っていたのが原因。

- `?fast=1` を足した。**AI が何秒後に喋るかだけ**を縮める（遊びの中身は変えない）
- 通しプレイの道具を、決め打ちの秒数から「助言が増えなくなるまで」
  「部屋が変わるまで」の待ちに変えた
- 演出の「間」は Playwright の reducedMotion で短い側にする（仕様として残っている道）

**1周 5分 → 82秒。** 20部屋を通しで回して読めるようになった。

### 速くしたので、部屋を全部測れるようになった

`tools/room-audit.mjs` を書いた。96部屋を何度も回して外れ値を出す。
通しプレイでは1周20部屋しか見えないので、
「いつも一目で分かる部屋」「いつも運任せの部屋」が埋もれていた。

**選択肢の名前が互いに含まれている部屋が2つあった。**

```
room_017  螺旋の階段 / 梯子 / 石段 / 斜めの板 / 縄の梯子
                      ↑ これが「縄の梯子」に含まれている
room_106  帳面 / 銭 / 面 / 縄 / 名前
                    ↑ これが「帳面」に含まれている
```

「縄の梯子だ」という助言が**両方に触れた**と数えられる。
読み手（人も AI も）が名前で照合するので、包含があるとその部屋だけ読みが壊れる。
「一度に触れてよい選択肢は2つまで」の検閲も誤爆する。

実測で room_017 は読めば当たる率が **48%**（全部屋平均62%、-8.9σ）。
名前を変えて解消した。検証（`npm run validate:rooms`）で弾くようにした。

### 外れ値を「揺れ」と間違えないようにした

最初は1つの種で最下位を並べていたが、**ほぼ全部が偶然だった**。
3つの種で最下位5部屋を出したら重なったのは1部屋だけで、
ある種で最下位の部屋が別の種では最上位（71%）に来た。

種を変えて何度も測り、
「3σを超え・どの種でも下振れし・10pt以上低い」ものだけを疑うようにした。
1部屋960試行で揺れの幅は±1.6pt。この形にすると
いまは該当なしで、わざと包含を戻すと -8.9σ で捕まる。

`npm run test` に入れた。

### 裏切りが得になっていないかも測った

全員挑戦者の裏切り者は罠を知っている＝一つ外せる。効きすぎると
「裏切ったほうが安全」になって、裏切りに命が懸かるという前提が壊れる。

| | 生存 |
|---|---|
| 裏切り者 | 76.6% |
| そうでない者 | 78.2% |
| **裏切りの得** | **-1.6pt** |

得になっていない。狙いどおりなので触らない。均衡の見張りに band を足した。

## 7回目（2026-09-10 06:30 UTC）　配信で発言できない99%に手を渡した

### 一度作って、測って、捨てたもの

まず「枠外の一斉投票を集計して挑戦者に見せる」を作った。
枠外にも嘘つきが混ざっているので票は罠に集まりやすく、
「群れに従うと死ぬ」がそのまま形になる——という筋書きだった。

`tools/crowd-check.mjs` で測った。

| 打ち手 | 1部屋あたり生存 |
|---|---|
| 票だけ見る | 23.3% |
| 票を無視する | **77.6%** |
| 票も足して読む | 73.5% |
| 票が集まった扉を避ける | 74.4% |
| 一番票が多い扉だけ疑う | 75.2% |

一番票が集まった扉の的中率は **23.3%**（当てずっぽうとほぼ同じ）。
**どう使っても、見ないほうが強い。**

助言には「必要な情報の中に罠が混ざっている」が、票は罠だけで情報が無い。
**純粋な罠を足すのは深みではなく雑音**なので、挑戦者の画面からは外した。

### 残したもの：枠外の一票は「自分の賭け」

票は盤面に何も影響しない。代わりに、入れた本人にだけ返す。

```
枠外の画面   言葉は届かない。だが票は届く
             （扉を押す）→ 「濡れた外套に入れた」
挑戦者が選ぶ → 「外した　通算 当0 外1」
```

盤面を汚さないので情報の均衡は動かないまま、
毎部屋「自分は当てられたか」が残る。1000人でも全員に等しく渡る。

### あわせて直した

崖っぷちの唯一の正直者は候補が1つ＝正解を正確に知っているのに、
画面が「生きる方は光った**1つ**のどれか。それ以上は分からない」と出していた。
知っていることを本人が過小に見る文言だった。
「光った扉が正解だ。あなただけが知っている」に変えた。

## 8回目（2026-09-10 14:30 UTC）　場が喋るようにした

一周まるごと書き出して、遊ぶ側の目で読んだ。

```
「顔を借りる。どれを被る」
  まさ   「笑った面か割れた面。決めきれん」
```

8人が**扉の名前しか言えない。** 並ぶのは8つの独白で、会話が起きない。
挑戦者がやっているのは「どの名前が何回出たか」の集計だった。
物差し（tools/rubric.mjs）は通常も崖っぷちも 7/7 で、

### 助言者どうしが互いを指せるようにした

```
  まさ   「破れた網だと思うが」
  ハルさん「太い網だ」
＞ まさ   「ハルさんは嘘をついている」
＞ ハルさん「まさを信じるな」
```

指す理由は、それぞれの持ち情報から出る。

| 立場 | 撃てる相手 |
|---|---|
| 嘘つき | 正解を口にした者（一番効く一手） |
| 協力者 | 自分の候補に無い扉を押した者 |
| 耳打ち | 死ぬと知っている扉を押した者 |

### 集計は雑音。でも捨てなかった

7回目に枠外の票を捨てたときと同じ物差しを当てた（tools/name-call.mjs）。

```
疑いが嘘つきに当たった率   32.2%   （でたらめに指すと 37.5%）
```

**全体で見ると当てずっぽう以下。** ここで捨てるところだったが、
中を割ったら別のものが出た。

```
協力者が撃ったとき  当たり 53.5%
嘘つきが撃ったとき  当たり 12.9%
```

撃たれた回数ごとに「その人が正解を口にしていた割合」を数えた（口を分けた最終形で）。

| 撃たれた回数 | 通常 | 崖っぷち |
|---|---|---|
| 0回 | 55.6% | 37.5% |
| 1回 | 42.8% | 75.5% |
| 2回 | 38.6% | **89.2%** |

**モードで向きが逆になる。**
崖っぷちは嘘つきが多数なので、群れが撃つのは真実を言った一人。
通常は嘘つきが少数なので、群れの疑いはだいたい当たる。

打ち手として測ると、それでも**撃たれた者を信じる側が両方で損をしない**。

| | 記録で重み付け | ＋撃たれた者を疑う | ＋撃たれた者を信じる |
|---|---|---|---|
| 通常 | 73.0% | 68.8% | 73.3% |
| 崖っぷち | 72.0% | 63.0% | **77.2%** |

疑う側は通常でも 4.2pt 損をする（重みを下げると、下げた先の助言まで捨てるため）。
本体の読み方（src/core/read-hints.ts）は**一方向だけ**にした。
モードで符号を切り替える枝は入れていない。片方向で両方とも損をしないので、
枝を増やすと読む側の規則も増えて、伝わらなくなる。

**「群れに従うと死ぬ」の裏返しで、群れが撃つ者は信じられる。**
崖っぷちではこれが 89.2% の手掛かりになる。

### 口を分けた。ここが一番大事だった

最初は「人を指す代わりに扉の話をしない」形で作った。測ったらこうなった。

```
通常　読める打ち手   76.6% → 70.2%
崖っぷち              70.3% → 66.4%
```

指すたびに扉の情報が減るので、**深くなる前に薄くなる。**
そこで**扉について言う口と、人を指す口を別にした。**
一部屋につき、扉の話が一つと、人を指すのが一つ。情報は減らない。

崖っぷちの腕の差 10.0→12.0pt。通常はほぼ変わらない（+0.3pt）が、場が喋る。
指す率 0.25 は振って決めた。0.35 まで上げると最良の打ち手が一つに固まる（最良差 6.6pt）。

区画を通して「ずっと撃たれている人」を見る打ち手も試した（65.3%）。
一部屋ぶんの撃たれ方を見るより弱い。撃たれ方は**その部屋のもの**で、
平均すると強い一発が薄まる。

撃つ側にも値段を付けた。**外した名指しは自分の記録に傷として残る**
（「あいつは嘘だ」が当たっていれば正、外していれば嘘）。
配役を覗かずに画面のものだけで決まるので、挑戦者が自分で検算できる。
さらに**自分の一言を出してからでないと撃てない**。
撃つだけで済むなら、自分の言葉を晒さずに人を潰せてしまう。

### 助言者の画面に「場」を作った

ここまで助言者の画面には**自分の一言しか出ていなかった。**

```
  テツ    売れ残った面か誰にも似ない面。決めきれん   [嘘だ][本当だ]
  ゴロー  迷うな、誰にも似ない面                     [嘘だ][本当だ]
  こより  迷うな、古い面                             [嘘だ][本当だ]
```

文面は送らせない（相手のIDと向きだけ送ってサーバーが書く）。
暴言の検査が要らないし、日本語を打てない人でも押せる。

思っていなかった効きがひとつあった。**枠外の人にも場が見える。**
7回目に渡した「自分の賭け」は、それまで助言を一つも見ずに入れる当てずっぽうだった。
いまは同じ言葉を読んでから入れられる。1000人ぶんの賭けが、勘から読みになった。

### 自分の道具が壊れていたのを4つ見つけた

作っている途中で、測る側・遊ぶ側の道具の不具合が出てきた。

1. **`tools/playtest-record.mjs` が最初の死で記録をやめていた。**
   部屋を「1部屋目 表口 1/4」という文字列で見分けていたので、
   死んで区画の頭に戻ると前と同じ文字列になり、以降ずっと空回りしていた。
   遊んだつもりで1部屋しか見ていない回があった。

2. **同じ道具が「◯◯で間違いない」を警告として読んでいた。**
   判定の言い回しを書き写していて、`/…|ない/` が「間違いない」を拾っていた。
   **一番強い断言を、逆の意味に読んでいた。**
   書き写しをやめて `src/i18n/ja.ts` から読むようにした。

3. **線を張る検査が、素振りを測っていた。**
   助言者ページは繋ぎ先（`VITE_PARTY_HOST`）が無いと素振りに落ちる。
   検査用のビルドで渡し忘れていたので、「本物の線を通した」つもりで
   素振りを見ていた。`pretest:live` で必ず繋ぎ先を埋めて建てるようにした。

4. **助言が届くたびに、打ちかけの文字が消えていた。**
   場を描き足すために盤面を描き直すようにしたら、入力欄も作り直していた。
   仲間の助言は数秒ごとに届くので、配信では**まず何も打てない。**
   部屋が変わったときだけ扉と入力欄を作り直すようにした。

あわせて、同じ名前が二人いると「あいつは嘘だ」が別人を指すので、
名簿の段で名前の重なりをほどくようにした（人間が仲間の名前を名乗ると起きる）。
