# 構成メモ

## なぜこの切り方か

フェーズ2（Steam 版）で作り直しが起きないことだけを基準に切ってある。

### 1. エントリポイントを最初から2つに割る

`index.html`（挑戦者）と `advisor.html`（助言者）は別バンドル。
Steam 版は挑戦者側だけを Tauri で包む。助言者ページは無料ブラウザのまま残る。
今ここを一つにしておくと、後で必ず割ることになる。

### 2. 正解の流れを型で塞ぐ

`RoomSchema` は `correct` と `deathMessage` を持つ。
`PublicRoomSchema` はそれを `omit` した型で、**挑戦者に渡るのはこちらだけ**。

```
Room (correct あり)  ──→ AdvisorGateway ──→ 助言者
   └─ PublicRoom (correct なし) ──→ 挑戦者
```

ローカル1人プレイでは同じプロセスに両方があるが、通信を繋いだときに
「うっかり挑戦者へ正解を送る」経路が型検査で落ちる。

### 3. 助言者を差し替え可能にする

`AdvisorGateway` は「助言者の名簿を持ち、部屋の開始を配り、ヒントを返す」だけを定義する。

| 実装 | 使う場面 | 状態 |
|---|---|---|
| `NullAdvisorGateway` | ローカル1人プレイ | 実装済み |
| `PartyKitGateway` | 配信 / 友達内 | 段階4 |
| `AiAdvisorGateway` | ソロモードの AI 嘘つき | フェーズ2 |

本体（`GameEngine`）はどれが刺さっているか知らない。
**人間かAIかでゲームロジックを分岐させない**のはこの一点で担保している。

### 4. 配信と友達内でロジックを分けない

`castRound()` は人数を見て自動で振る舞いを変える。

- 助言者が発言枠以下（友達モード）→ **全員が発言枠**
- 発言枠を超える（配信）→ 抽選または指名で絞る
- 嘘つきは発言枠の中から 1〜2 人。枠が5人未満なら必ず1人
  （枠3人で嘘つき2人だと読み合いが成立しないため）
- 嘘つきはラウンドごとに再抽選

### 5. 「間」を本体が持つ

死亡演出の 0.8 秒の無音は UI の都合ではなく仕様。
`GameEngine` の phase が `hush → reveal → verdict` と進み、
UI は各段を再生して `advancePresentation()` を呼ぶ。
通信を繋いだとき、この進行をサーバーが持てば全員の画面で「間」が揃う。

### 6. 助言者ページの初速

助言者ページが読み込むもの：

- JS 約 4.2 kB（gzip）
- CSS 約 1.7 kB（gzip）
- Webフォント **なし**（本文は `system-ui`）
- 画像 **なし**（仮絵は data: URI でコード内生成）

zod は `schema.ts` にあるが、助言者ページは `limits.ts`（定数のみ）を読むので
検証ライブラリが初期表示の経路に載らない。ここは意識して守ること。
