# 構成メモ

## なぜこの切り方か

フェーズ2（Steam 版）で作り直しが起きないことだけを基準に切ってある。

### 1. エントリポイントを最初から2つに割る

`index.html`（挑戦者）と `advisor.html`（助言者）は別バンドル。
Steam 版は挑戦者側だけを Tauri で包む。助言者ページは無料ブラウザのまま残る。
今ここを一つにしておくと、後で必ず割ることになる。

### 2. 正解の流れを型で塞ぐ

`RoomSchema` は `correct` と `deathMessage` を持つ。
`PublicRoomSchema` はそれを `omit` した型で、**挑戦者に渡るのはこちらだけ**。

```
Room (correct あり)  ──→ AdvisorGateway ──→ 助言者
   └─ PublicRoom (correct なし) ──→ 挑戦者
```

ローカル1人プレイでは同じプロセスに両方があるが、通信を繋いだときに
「うっかり挑戦者へ正解を送る」経路が型検査で落ちる。

### 3. 助言者を差し替え可能にする

`AdvisorGateway` は「助言者の名簿を持ち、部屋の開始を配り、ヒントを返す」だけを定義する。

| 実装 | 使う場面 | 状態 |
|---|---|---|
| `NullAdvisorGateway` | ローカル1人プレイ | 実装済み |
| `SocketAdvisorGateway` | 賭場（人間の助言者） | 実装済み |
| `AiAdvisorGateway` | ソロモードの AI 嘘つき | フェーズ2 |

本体（`GameEngine`）はどれが刺さっているか知らない。
**人間かAIかでゲームロジックを分岐させない**のはこの一点で担保している。

### 4. 配信と友達内でロジックを分けない

`castRound()` は人数を見て自動で振る舞いを変える。

- 助言者が発言枠以下（友達モード）→ **全員が発言枠**
- 発言枠を超える（配信）→ 抽選または指名で絞る
- 嘘つきは発言枠の中から 1〜2 人。枠が5人未満なら必ず1人
  （枠3人で嘘つき2人だと読み合いが成立しないため）
- 嘘つきはラウンドごとに再抽選

### 5. 「間」を本体が持つ

死亡演出の 0.8 秒の無音は UI の都合ではなく仕様。
`GameEngine` の phase が `hush → reveal → verdict` と進み、
UI は各段を再生して `advancePresentation()` を呼ぶ。
通信を繋いだとき、この進行をサーバーが持てば全員の画面で「間」が揃う。

### 6. 助言者ページの初速

助言者ページが読み込むもの：

- JS 約 4.2 kB（gzip）
- CSS 約 1.7 kB（gzip）
- Webフォント **なし**（本文は `system-ui`）
- 画像 **なし**（仮絵は data: URI でコード内生成）

zod は `schema.ts` にあるが、助言者ページは `limits.ts`（定数のみ）を読むので
検証ライブラリが初期表示の経路に載らない。ここは意識して守ること。

## 段階4（通信層）

**PartyKit で書いた。** 費用の判断は要らない
（SQLite バックエンドの Durable Objects は Workers 無料プランで使える。
`docs/COST.md`）。

### どこで何が動くか

```
挑戦者の画面 ─┐                        ┌─ 助言者の画面（スマホ）
              ├─ WebSocket ─ 部屋 ─────┤
仲間の画面 ───┘   （Durable Object）   └─ 助言者の画面（スマホ）
                        │
                        └ RoomSession → GameEngine → CompositeAdvisorGateway
                                                      ├ SocketAdvisorGateway（人間）
                                                      └ AiAdvisorGateway（足りないぶん）
```

**ゲーム本体はサーバーで回す。** 全員挑戦者モードで見知らぬ相手と
遊ぶのに、誰か一人の端末を権威にしたくないから（正解を持っている側に
なれてしまう）。ソロは今までどおりブラウザの中だけで完結する。

| ファイル | 役 |
|---|---|
| `party/server.ts` | PartyKit の接ぎ手。薄い。眠らせない（盤面をメモリに持つため） |
| `src/core/room-session.ts` | 部屋ひとつぶんの進行。**通信を知らない**（Sink 越し） |
| `src/core/socket-gateway.ts` | 繋がっている人から助言を受け取る `AdvisorGateway` |
| `src/challenger/remote-game.ts` | 遠くの部屋を、ローカルの本体と同じ顔にして返す |
| `src/advisor/live-connection.ts` | 助言者ページの実接続。zod を読まない |

`RoomSession` が WebSocket を知らないので、繋がずに全部試験できる
（`tools/test-party.mjs`）。実際に線を張る試験は別（下記）。

### 答えが漏れない仕組み

| 誰に | 何を送るか |
|---|---|
| 挑戦者 | `room/view`（画面ぶん丸ごと）。部屋は `PublicRoom`、`liarLog` は載せない |
| 助言者 | `round/open`。**自分あての `knowledge` だけ**。一人ずつ別のメッセージ |
| 全員 | `room/state` `round/hints` `round/result` `section/answer` `game/over` |

`liarLog` を載せないのが要点。今の部屋の嘘つきが分かると助言の意味が消える。
終わったあとの開示は `game/over` が別に運ぶ。
`tools/test-party.mjs` と `tools/party-live.mjs` が毎回ここを見ている。

配役が開くのは**二か所だけ**。区画を離れるときの `section/answer` と、
一周の終わりの `game/over`。それ以外の便には載らない。

> 判定（`verdict`）に `liars` を積んでいた時期がある。画面には出していないが、
> 一部屋抜けるたびに区画ぶんの配役が挑戦者の線へ流れていた。顔ぶれは区画のあいだ
> 変わらないので、**一部屋目の判定を覗くだけでその区画の読み合いが終わっていた。**
> 型から外して、`tools/answer-check.mjs` が毎回見ている。

### 信用できない側

ブラウザ→サーバーは `ClientMessageSchema` を必ず通す。
助言の検査（暴言・字数・連投・選択肢の数え上げ）は `GameEngine` の
受け口にあるので、サーバーで回す以上そこを必ず通る。
二重に持つと片方だけ直る事故が起きるので、置き直していない。
弾いたことは `onHintRejected` で本人に返す。

締切もサーバーが持つ。挑戦者の画面任せにすると、閉じられた部屋で
助言者が待たされ続ける。

### 区画の答え合わせ

演出の段に一つ足した。`hush → reveal → verdict → **answer** → 次の部屋`。

`answer` は**区画を離れるときだけ**挟まる。抜けたとき、あるいは深く行って
落ちたとき（顔ぶれと配役はどちらでも引き直される）。命が尽きたときは出さない
——終わりの画面が区画ぶん全部開くので二重になる。区画の頭で落ちたときも出さない
（記録が「正1 嘘0」しかない紙が8人ぶん並ぶだけで、読み合いの答えにならない）。

離れる条件は `GameEngine.answerForLeavingSection()` と `afterVerdict()` の
二か所に書いてある。**食い違うと、紙だけ出て区画が変わらない**（あるいは逆）ので、
`tools/answer-check.mjs` が両方を突き合わせている。

送る段は遊び方で違う。一人用と賭場は**挑戦者が押して**送る（読み終わるまで待つ）。
全員挑戦者は6〜8人の合図を待てないので、`untilMs` を載せて**時間で**送る。

助言者にも `section/answer` を配る。助言者は自分の役しか知らないので、
嘘が刺さったのかも、正直に言ったのに信じられなかった理由も、
ここまで一度も返っていなかった。

### 言い回しは数も言語で揃える

文言表は鍵（`narrow` など）が揃っていれば検査を通るが、**中身の数**は
揃わない。20回目に日本語の二択の型を4→14種にしたとき、英語を4種のまま
置いていた（`tools/test-locale.mjs` が数を見るようになったのは23回目）。

字数の上限も言語で意味が違う。英語のラベルは中央12字なので、
二つ並べて上限42では残り4字——`「 or 」`しか収まらず、
二択の組の18.4%で言い方が一つも選べなかった（日本語は0.0%）。48 に上げた。
**「一度に二つまで」を守っているのはこの上限ではなく**
`moderation.countChoicesMentioned` なので、緩めても性質は崩れない。

### 音は拍にだけ付ける

10種。`Sfx` の名前がそのままファイル名（`public/snd/<name>.wav`）になる。

鳴らすのは**拍**だけで、流れてくるものには付けない。助言は毎部屋7件届くので
鳴らすと音が意味を失う——鳴るのは人を指した一言（`accuse`）だけ。
区画の答え合わせ（`answer`）は一周で3〜5回しか来ないので、そこには尺を使う。

名前を足して実物を置き忘れても**型検査は通り、Howler も黙っている**ので、
`tools/asset-check.mjs` が名前・実物・生成の台本の三つを突き合わせている。

### 席は喋る人に回る

発言枠は区画ごとに抽選で引く。重みは三つ。

| 何を | 重み |
|---|---|
| 手を挙げた | ×4 |
| 枠外の賭けを当てている | 当たり1つごとに ×1.15（上限 ×2） |
| **前の区画で席にいたのに一言も書かなかった** | **×0.15** |

三つめが 19回目に足したもの。線が切れた人の席は AI が引き取るが、
**居るのに黙っている人**は素通りで、席が区画のあいだ空いたまま残っていた。

0 にはしない（確定で落とすと、打つのが遅い人が二度と座れない）。
数えるのは扉について言った人だけで、人を指す一手は数えない。
死んで引き直したぶんも数えない。`tools/quiet-seat-check.mjs` が見ている。

### 部屋の結果は、線を増やさずに返す

発言枠にいた人へ「あなたの言葉で通った／死んだ／信じられなかった」を返すが、
**そのためのメッセージは作っていない。**

`round/result` は前から選んだ扉と正解を全員に配っている。自分の一言は
自分の画面にある。だから助言者ページの中で突き合わせれば出せる
（`LiveConnection.reportMyRound`）。判定は記録を付けるのと同じ
`wasTruthful` を使い、正解の代わりに**選んだ扉**を渡す
——「Xは死ぬ」と言って X を避けられたなら信じられている、が同じ形で出る。

知らせ（`.board-notice`）は部屋が変わったら消す。消さなかったので、
枠から外れた人の画面に前の部屋の結果が貼り付いたままになっていた。

### 疑いの札は公開する。ただし全員挑戦者では配らない

助言の各行に置ける疑いの札（`hint-doubt`）は、**相手に伝わる。**
`challenger/doubt` で送り、サーバーは助言者へ `room/doubts` を配る。
札の付いた本人の画面には頭に一行（`.role-doubt`）、
ほかの助言者には場の行に印（`.floor-mark`）が出る。挑戦者には送り返さない
（置いた本人の画面にはもう出ている）。

配らないのは**全員挑戦者モードだけ。** あちらは挑戦者が何人もいるので、
誰の札を配るのかが決まらない。`PartyBoard` の札は画面の中だけに残す
（言い回しも `doubtHintPrivate` で分けてある）。

効くのは**次の部屋から。** 部屋の助言はもう出ているので、読んでから置いた札が
その場の言葉を書き換えては読み合いにならない。`GameEngine.doubtedIds` は
`openRound` の `doubtedIds` に載り、AI の嘘つきは札の付いた者を撃つ重みを
`RUN.doubtPileOn`（2.5）倍にする（`chooseCall` の `CallBias`）。
顔ぶれが変わる部屋で札は捨てる——前の区画の読みで新しい人が撃たれるので。

公開に踏み切る前に測ったのは二つ（`tools/doubt-probe.mjs`、`npm test` に入れた）。

| 見たもの | 結果 |
|---|---|
| 「二人以上から撃たれた者ほど本当のことを言っている」が壊れないか | 崖っぷち +44.1pt → +43.6pt、通常 −8.1pt → −10.9pt。倍率6まで向きも強さも保つ |
| 外した札に代金が付くか | 通常：協力者に置いた札の持ち主が撃たれる回数 0.26 → 0.66（札の無い協力者は 0.18） |

代金が付くのは、嘘つきが撃てる相手が元から限られている（正解を口にした者・
罠を「死ぬ」と言った者）ため、札はそのあいだの**選り好みしか動かさない**から。
当たった札は何も呼ばず、正直に正解を言った人へ置いた札だけが
その人を集中砲火に晒す。崖っぷちはほぼ全員が嘘つきなので外した札がまず起きない
（実測 札の精度100%）。

### 押された者は言い切る

札を置かれた者は、次の一言を**扉ひとつの言い切り**にしなければならない。
迷いの言い方（「たぶん」「どっちか」）も、二つ挙げる形も通らない
（`moderation.isCommitted` / 断る理由は `mustCommit`）。

**AI だけの作法にしない。** 人間の助言者も同じ規則で弾かれる
（`GameEngine.hint` が `checkHint` に `pressed` を渡す）。手元でも同じ関数で
止めるので、押してから断られることはない。札は部屋の途中で置かれるので、
入力欄の検査は**その場の view を読む**（作った時点の写しを見ていて
素通しになっていた）。

置く側の取り引きはこう。

| 得 | 損 |
|---|---|
| 言い切らせれば次の部屋で正誤が付く＝**記録が早く固まる**（嘘つきは罠を押すしかない） | その人の**迷いが読めなくなる**。迷いはこのゲームで一番強い手掛かり |
| 嘘つきの「迷ったふり」で紛れられなくなる | 嘘つきが札の付いた者へ寄る（外した札は本人を集中砲火に晒す） |

測ったもの（`tools/press-probe.mjs`、`npm test` に入れた）。

| 見たもの | 通常 | 崖っぷち |
|---|---|---|
| 押された一言の当たり（嘘つき／協力者） | 15.1% / 54.4% | 15.7% / 協力者はまず押されない |
| 記録で読んだときの当たり | 65.0% → 71.5% | 40.0% → 53.0% |
| 迷いの言い方が場に残る率 | 63.4% → 54.9% | 52.8% → 34.0% |

均衡は `PRESS=2 node tools/rubric.mjs` で確かめる。通常 7/7・崖っぷち 7/7 のまま、
腕の差は 12.7→11.6pt／21.9→19.3pt と少し縮む（迷いを削るぶんの代金）。
全員を押した形（`PRESS=8`）でも 7/7 だったので、枚数の上限は置いていない。

### 一部屋につき、口は二つ

助言者は一部屋で二つ喋る。

| 口 | 中身 | 送り方 |
|---|---|---|
| 扉について | 「割れた面か目のない面のどっちか」 | `advisor/hint`（文面。暴言の検査を通す） |
| 人を指して | 「ノブは嘘だ」 | `advisor/point`（**相手のIDと向きだけ**。文面はサーバーが書く） |

分けてあるのは、同じ口にすると指すたびに扉の情報が減るから
（実測で読める打ち手が 5pt 落ちた）。`Advice.kind` が `'door'` / `'call'`。

人を指した一言の正誤は、**指した相手の扉についての言が嘘だったか**で決まる
（`src/core/name-calling.ts` の `resolveTruth`）。配役を覗かないので、
挑戦者が画面のものだけで検算できる。返すのは一言ごと。
人ごとにまとめると、撃った当たり外れが扉の当たり外れを上書きして消える。

名前で照合するので、**同じ名前が二人いると別人を指す。**
`CompositeAdvisorGateway.roster()` の段で重なりをほどいている。

### 全員挑戦者モードは別の本体で動く

命が人ごとにあり、死んでも部屋が前に進むので、通常モードとは
規則がまるごと違う。一緒にすると読めなくなるため `src/core/party-engine.ts`
に分けてある。配役・知識・言葉の検査は共通のものを使う。

サーバー側では `RoomSession` がモードを見て使い分ける。
全員挑戦者では**演出の段もサーバーが刻む**（全員の画面で同じ間にするため）。
画面側は `PartySource` 越しに描くので、ローカルでも遠くの部屋でも同じ盤面。

### 待合室（野良）

`party/lobby.ts`。部屋とは別の party に立ててある。
ゲームを知らず、同じモードを待っている人に合言葉を配るだけ。

### 残っているもの

- 連戦（同じ顔ぶれで次の周へ）
- 通報の積み上げを部屋をまたいで持つこと
- 絵（生成サービスの規約確認 → 10枚テスト）

## 多言語

- UI の文言は `src/i18n/{ja,en}.ts`。`ja.ts` が形の正で、他はその形に揃える（型で強制される）
- **部屋データも言語ごとに持つ**。`{ "ja": "…", "en": "…" }` の形で JSON に入っている
- 言語の決め方：`?lang=` → 保存された選択 → ブラウザの設定 → 日本語
- 追加するときは `src/i18n/locales.ts` に足し、`ja.ts` と同じ形の表を作り、
  `scripts/translate-rooms.mjs` に対訳を足す

言語を足すと部屋データの検証が自動で効く（`npm run validate:rooms`）。
訳が抜けていれば通らない。

## 書体

Koshin Pop（恒紳ポップ、SIL OFL）を見出しに使う。
元は1ウェイト 2.1MB あるので、そのままでは載せられない。

```bash
npm run font   # 使用文字だけに絞る
```

- `koshin-display.woff2` … 209KB / 799字。挑戦者画面（部屋の文言まで含む）
- `koshin-role.woff2` … 48KB / 163字。助言者ページの見出しだけ

助言者ページの本文はシステムフォントのまま。初期表示を書体の読み込みで待たせない
（`font-display: swap`）。文字化けが出ていないかは `node tools/check-font.mjs` で
実際に描画して確かめている。

**この書体で行く（決定済み）。**
「弾ける・跳ねる」性格は闇市・公開処刑という主題と逆を向いているが、
見世物小屋の口上（陽気に処刑を告げる）として成立している。暗い地の上では
手描きの興行看板のように見える。見出しから外す案は採らない。

以降、見出しの書体を変える提案は蒸し返さないこと。

## 荒らし対策

`src/core/moderation.ts` に集約。**本体とサーバー（段階4）が同じ関数を通す。**
クライアント側の検査は体験のためのもので、防御はサーバーで同じ関数を通して成立する。

- 文字数（20字）、連投（同一助言者2.5秒）、同文の再送
- NGワード。NFKC正規化＋記号除去＋繰り返し畳み込みで伏せ字を潰す
- **番号と位置で指す言い方の禁止**。「1234は罠」で全選択肢を潰す攻撃を封じる
- **一度に触れてよい選択肢は2つまで**
- 通報。別々の3人から通報されるとその人の助言は届かなくなる
- 入室上限

助言者ページでは**送信できない文面はボタンが押せない**（押してから断らない）。
理由もその場に出る。

### 選択肢の名前に位置語が入る場合

「右手」「端の薄い氷」「手前の椀」のように、名前そのものに位置語が入ることがある。
`isPointing()` は**先に選択肢の名前を取り除いてから**調べる。
これをやらないと正当な助言が黙って消える（実際に消えていた）。
