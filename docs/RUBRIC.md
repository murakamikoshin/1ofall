# 「面白いか」の基準と、いまの数字

実際の10人には聞けないので、**これまでの検証で「面白くない」と分かった症状を裏返して基準にした**。
`node tools/rubric.mjs` で再現できる。

| 項目 | 狙い | なぜ |
|---|---|---|
| 決断率 | 50%以上 | 一目で決まる部屋ばかりだと確認作業になる。以前は7割が一目で決まった |
| 群れの罠率 | 10%以上 | 票が集まった選択肢が必ず正解だと、群れに従うだけの作業になる |
| 腕の差 | 8pt以上 | 素朴な打ち手と読める打ち手の差。以前は0.6ptしかなかった |
| 生存率 | 72〜85% | 低いと理不尽、高いと緊張が消える |
| 1周の長さ | 10〜15分 | 配信向けゲームの相場から。以前は18秒だった |
| 短命率 | 15%未満 | 5部屋以下で終わる周が多いと、何も見られずに終わる |
| 最良差 | 6pt以内 | 最良の打ち手が一つに固まると攻略が終わる |

打ち手は6種類を同じ部屋・同じ助言に食わせて比べる（当てずっぽう／数えるだけ／
記録で重み付け／迷いを信じ記録も見る／一番信用できる一人に賭ける／票が集まりすぎたものを避ける）。
「黙らせる」も含めて1周を通しで回す。

## 全員挑戦者モード：7 / 7（三つで最良）

全員が同じ部屋を歩く。仲間も選び、死ぬ。挑戦者自身にも部分情報（三択）が配られる。
嘘つきは**どれが死ぬかだけ知っていて、正解は知らない**。

| 打ち手 | 生存率 |
|---|---|
| 当てずっぽう | 19.2% |
| 自分の情報だけ | 33.2% |
| 数えるだけ | 50.9% |
| 記録で重み付け | 77.0% |
| **迷いを信じ記録も見る** | **81.2%** |

| 項目 | 値 | |
|---|---|---|
| 決断率 | **79.4%** | ○ |
| 群れの罠率 | **43.9%** | ○ |
| 腕の差 | **31.1pt** | ○ |
| 生存率 | 82.0% | ○ |
| 1周 | 14.1分 | ○ |
| 短命率 | 0.6% | ○ |
| 最良差 | 4.2pt | ○ |

**数えるだけが50.9%まで落ちる。** このセッション中ずっと戦ってきた
「集計で解ける」病に、この形が一番強い。

理由は三つ。

1. **他人の話の価値が +48pt。** 自分の情報だけなら33.2%、他人も読むと81.2%。
   助言者モードの腕の差が10pt前後なので桁が違う
2. **嘘つきにも命が懸かる。** 助言者モードでは嘘をつくコストがゼロだった
3. **同時に選んで結果が開くので、言ったことと選んだことのずれが見える。**
   「隅の袋で間違いない」と言った者が手前の椀を選んでいたら、それが証拠になる

### 二つの壊れ方を潰してある

**嘘つきが正解を知ると、一度も死なないので8部屋で丸わかりになる**
（死亡回数 正直者2.16回 / 嘘つき0.00回）。
罠だけを知る形にすると 2.16回 / 2.04回 で見分けがつかなくなる。生存率は変わらない。

**死んだ仲間は次の部屋を休む。** これが無いと、嘘つきが「自分も罠に落ちて見せる」
camouflage を無料で使える。休むぶん声を失うので、賭けになる。

## 崖っぷちモード：6 / 7

正直者はただ一人で、**その一人だけが正解を正確に知っている**。
残りは全員嘘つきで同じ罠へ誘う。顔ぶれは5部屋ごとに入れ替わるので、狩りを何度もやり直す。

| 打ち手 | 生存率 |
|---|---|
| 当てずっぽう | 19.3% |
| 数えるだけ | 59.4% |
| **記録で重み付け** | **67.4%** |
| 一番信用できる一人に賭ける | 58.1% |

| 項目 | 値 | |
|---|---|---|
| 決断率 | 56.3% | ○ |
| 群れの罠率 | 34.3% | ○ |
| 腕の差 | 9.5pt | ○ |
| **生存率** | **68.9%** | **×**（狙いは72〜85%） |
| 1周 | 11.2分 | ○ |
| 短命率 | 0.0% | ○ |
| 最良差 | 1.1pt | ○ |

**外れているのは生存率だけ。** 通常モードが82.1%なのに対して68.9%で、
崖っぷちという名前どおり厳しい。緩めれば基準は満たせるが、
そうすると通常モードとの差が消えるので、いまは外したままにしている。**要判断。**

## 設計を作り直した経緯

1. 全員が正解を知る → 多数決で解ける（全構成で生存率100%）
2. 助言を伏せて数通だけひらく → 運ゲー（ひらく時点で判断材料が無い）
3. 協力者に正解を教えない → まだ数えるだけで解けた（腕の差0.6pt）
4. 嘘つき全員に同じ罠を見せる → 嘘が1点に集まり、群れが罠になる
5. 嘘つきを半数にし、毎回は嘘をつかせない → 記録が効くようになる
6. 嘘つきが迷ったふりもできるようにする → 「断言＝嘘つき」を機械的でなくする
7. 黙らせるを評価に含める → 上手い人だけが使える道具として腕の差が開いた

### 途中で捨てた案

- **属性の制約**：「一番多くの制約を満たす選択肢を選ぶ」＝最大の整合集合を探すことなので、
  結局また数える作業になる。部屋データに属性を付ける前に気づけた
- **嘘つきの人数を区画ごとに振る**：変動が区画単位でしか起きず、
  嘘つき1人の区画は6部屋まるごと確認作業になった
- **何も知らない助言者を混ぜる**：半分入れると生存率が61%まで落ち、
  落ちたぶんがそのまま運になった

## 言語ごとの検証（2026-09-09 追加）

基準はすべて日本語で測っていた。英語で測ったら**壊れていた。**

- 助言の言い回しが日本語で直書きされていて、英語では
  「New straw sandalだ」「たぶんMuddy clog」になっていた
- 真偽の判定（記録の正誤）が日本語の言い回し専用で、英語では素通り
- 番号と位置の禁止も日本語専用。英語の `second` `left` `middle` が通っていた
  ＝「1234は罠」の抜け道が英語で開いていた
- 文字数上限20文字は日本語向けの値。英語のラベルは長いので枠が足りなかった（42文字に）

直した後、英語でも同じ数字になる。

| | 日本語 | 英語 |
|---|---|---|
| 全員挑戦者 | 7/7（腕の差31.1pt） | **7/7（腕の差32.0pt）** |
| 崖っぷち | 6/7 | 6/7（同じ1項目） |

`npm run test` に言語ごとの見張りを入れた。
他言語の混入・文字数超え・空の助言・言い回しの偏り・真偽判定・番号禁止を全言語で確認する。
このテストを書いた直後に、英語の真偽判定がもう一件壊れているのを捕まえた
（冠詞を直したときに判定パターンを合わせ忘れていた）。

## この基準の限界

**実際の人間に聞いていない。** ここで測っているのは
「機械的な攻略に対してどれだけ抵抗があるか」であって、面白さそのものではない。

そして測定の相手は**AI助言者が定型文で喋る条件**で、これは機械的な攻略が最も効く状況。
人間が20文字を自由に書く本番では、言い回しの解釈という機械化できない層が乗る。
そこは通信層を繋いでからでないと確かめられない。
